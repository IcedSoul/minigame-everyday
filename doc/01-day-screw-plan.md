## 一 为什么从这款开始

- **核心循环最简单**：点击 → 入槽 → 三同消除 → 槽满判负 → 拆完判胜，没有任何附加系统
- **美术资源极少**：一组同色螺丝 + 一块木板 + 几个颜色槽位，足够
- **数据结构清晰**：螺丝 = `{id, color, x, y, zLayer}`，几乎一个数组搞定
- **适合给系列起势**：1 天能跑通完整循环 + 录 GIF + 写复盘，节奏不被首日拖死

## 二 核心玩法拆解

### 2.1 一句话规则

> **场景由"板子"组成，每块板子上固定有 3 颗及以上同色螺丝；上层板子会遮挡下层板子，只能点未被遮挡的板子上的螺丝；点击的螺丝按颜色塞入顶部 4 色螺丝盒，盒满 3 颗即消除并替换为新颜色盒；没有匹配颜色盒的螺丝进入底部备选区（最多 5 格），超过即失败；所有螺丝拆光即胜利。**

### 2.2 三条核心规则（必须做对）

#### 规则 1：板子遮挡

- 场上由若干"板子"（Board）构成，**每块板子上固定 3 颗及以上螺丝**
- 板子有 z 轴层级，**上层板子的矩形 AABB 覆盖到下层板子时，下层板子上所有螺丝都不可点**
- 只有"完全未被任何上层板子覆盖"的板子才可交互
- 当一块板子上所有螺丝都被拧走，该板子消失，原本被它压住的下层板子解锁

#### 规则 2：顶部 4 色螺丝盒

- 顶部固定 **4 个** 螺丝盒，每个盒子有一个颜色（来自当前关卡的颜色池）
- 点击螺丝时：
  - 若**顶部存在同色螺丝盒** → 螺丝飞入该盒子，盒子计数 +1
  - 若**顶部不存在同色螺丝盒** → 螺丝进入底部备选区
- 任意螺丝盒计数达到 3，**立即消除该盒子并从颜色池补一个新颜色盒**（保持 4 个）

#### 规则 3：备选区 5 格惩罚

- 底部备选区固定 **5 格**
- 进入条件：屏幕上没有同色螺丝盒可放
- 备选区里的螺丝**纯惩罚，不参与任何消除**（即便备选区里凑齐 3 同色也不消）
- 备选区已满 5 个时，再有新螺丝进入 → **游戏失败**（先判后塞）

#### 胜负条件

- **胜利**：所有板子上的螺丝拧光（屏幕上不再有可点击的板子）
- **失败**：备选区第 6 次塞入触发

### 2.3 状态机

```

            │  玩家点击板子 B 上的螺丝 Si（color=C）  │
            │  前置：B 未被任何上层板子覆盖             │
            └────────────┬────────────────────────────┘
                         │
              ┌──────────┴────────────┐
              │ 顶部 4 盒中存在 color=C ? │
              └──────────┬────────────┘

                │                   │
                ▼                   ▼
       目标盒 +1 颗 Si        ┌─备选区是否已 5 满 ?─┐
                │             是                      否
       ┌────────┴────────┐    │                       │
       │ 盒计数 == 3 ?    │    ▼                       ▼
       └────────┬────────┘ GAME OVER         备选区 +1 颗
        是              否
         │              │
         ▼              │
   消除盒+补新色盒      │
         │              │
         └──────┬───────┘
                ▼
       从板子 B 移除该螺丝
                ▼
       板子 B 上是否还有螺丝 ?─否─→ 移除板子 B（解锁下层）
                │
               是
                ▼
       场上是否还有板子 ?─否─→ LEVEL CLEAR

                ▼
```

### 2.4 与同类的差异点（设计要点，别抄混）

| 游戏 | 区别 |
|---|---|
| 《羊了个羊》 | 同色 3 个就地消除，**没有顶部盒子**这一层 |
| 《消个水果》 | 没有顶部盒子，缓冲槽满 7 即败，同色相邻消 |
| **《打个螺丝》** | **板子层级遮挡 + 顶部 4 色盒（满 3 消并换色）+ 5 格备选区惩罚** |

> 三件套缺一不可：板子遮挡决定"先点哪个"的策略性，4 色盒决定"目标分布"，备选区决定"试错成本"。

## 三 MVP 范围与非目标

### 3.1 MVP 必做（Day 1 范围）

- ✅ 一个固定关卡：6-8 块板子 + 3 层遮挡（z=0/1/2），共 18 颗螺丝（3 的倍数），3 种颜色各 6 颗
- ✅ 板子遮挡判定 + 未遮挡板子的螺丝可点
- ✅ 顶部 4 色螺丝盒 + 满 3 消除并补新色
- ✅ 备选区 5 格 + 超出即失败（先判后塞）
- ✅ 所有板子拆光即胜利
- ✅ 失败 / 胜利提示 + 重开

### 3.2 MVP 不做（明确砍掉）

- ❌ 多关卡 / 关卡进度系统
- ❌ 道具（撤回、洗牌、加缓冲格）
- ❌ 广告位 / 复活机制
- ❌ 螺丝飞向盒子的弧线动画（用直线 tween 代替）
- ❌ 木板掉落物理动画
- ❌ 计分 / 排行榜
- ❌ BGM（第一轮连音效都先不做）

> **原则**：第一天的产出价值不在"做得多"，在"核心循环跑得通、玩起来有那么点意思"。

### 4.3 关键数据结构

```js
// 颜色池：当前关卡使用 3 种颜色（red/yellow/blue）
const COLORS = ['red', 'yellow', 'blue', 'green'];

// 螺丝
{ id, color, boardId, offsetX, offsetY }

// 板子（持有 N 颗螺丝，z 越大越靠上）
{ id, x, y, w, h, z, screwIds: [...] }

// 顶部螺丝盒（固定 4 个）
{ id, color, count }   // count 达到 3 立即消除并补新色

// 备选区
buffer: Screw[]   // 长度上限 5

// 全局状态
{ boards, boxes, buffer, status: 'playing' | 'win' | 'lose' }
```

### 4.4 板子遮挡判定算法

```
对每块板子 B：
  unlocked(B) = true
  对所有满足 z > B.z 的板子 B'：
    若 AABB(B') 与 AABB(B) 相交 → unlocked(B) = false
  若 unlocked(B) = false：B 上所有螺丝置灰且禁用 input
  若 unlocked(B) = true：B 上所有螺丝可点击
```

每次拆除一颗螺丝后，若板子空了，移除该板子；然后**全量重算遮挡状态**（关卡规模小，无需优化）。

## 八 已识别的坑（实战中已踩过）

1. **`window.devicePixelRatio` 在小游戏 sandbox 里是 `undefined`** —— 必须先用 `wx.getSystemInfoSync()` 拿 viewport，否则 `.toFixed()` 直接崩
2. **`Phaser.WEBGL` 在 wx-compat 预览环境会让截屏 readback 超时** —— 改用 `Phaser.CANVAS`，体积小、稳定
3. **`scale.zoom: 1 / DPR` 在没有 DOM container 的环境无效** —— 直接用 css 像素当 width/height，不要 zoom
4. **盒子集满 3 颗的时机** —— 塞入后**立即**调用消除并刷新 UI，不要 setTimeout
5. **备选区超出判定要"先判后塞"** —— 先看 buffer.length 是否到 5，是就直接 lose；不要塞进去再判
6. **板子遮挡判定要在每次拆螺丝后全量重算** —— 关卡规模小（<20 板），无需增量优化
7. **微信小游戏没有 DOM** —— 不能用 `document` / `window.alert` / `document.fonts.ready` 等
